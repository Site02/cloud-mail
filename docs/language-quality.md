# 语言覆盖与发布准入

## 当前范围

语言选择器提供 16 种语言：简体中文、英语、西班牙语、法语、日语、韩语、德语、巴西葡萄牙语、俄语、意大利语、印尼语、越南语、土耳其语、阿拉伯语、印地语、繁体中文。浏览器语言是默认值，手动选择保存在当前站点；公开邮箱与登录页之间的手动选择会随导航传递。

先前准备的 85 种额外语言含有登录、删除、隐私、附件等关键文案的错译，未列入选择器、安装清单或构建产物。不能据此宣称已有百余种完整界面语言。

## 新语言进入选择器的条件

1. 在语言注册表中明确语言标签、文字体系、页面方向和日期词包。区域变体只能在文字体系兼容且文案适用时合并。[BCP 47](https://www.rfc-editor.org/rfc/rfc5646) 与 [W3C 页面方向指南](https://www.w3.org/International/questions/qa-html-dir) 用作标签和排版依据。
2. 完成前端 498 项及服务端 128 项文案，并检查所有占位符、按钮含义和错误后果。公开邮箱“知道地址即可读取”、本浏览器内的手动清理、浏览器可能逐出缓存、附件失效、账号权限、账户软删或永久删除、Webhook 密钥和删除确认必须逐条复核。重复文本和大量英语照搬会被自动检查拦截；自动检查不能代替语义审阅。候选 JSON 可在 `mail-vue` 目录运行 `npm run check:locale -- <语言代码> <前端词典.json> <服务端词典.json>`；通过仅代表结构检查合格。
3. 按 [CLDR 复数类别](https://cldr.unicode.org/index/cldr-spec/plural-rules)验证 0、1、2、3、5、11、21、101 等数量。不能把单一的英文复数句型直接复制到俄语、阿拉伯语等语言。
4. 核查组件提示、编辑器语言、日期、服务端消息、网页标题及两份安装清单。若某处仍回退英语，应标出实际覆盖范围，不得称为完整翻译。
5. 在桌面和窄屏检查选择器、长文本、从右到左布局、邮箱地址与验证码方向；分别检查在线、离线、错误、邮件正文和附件操作。独立审阅后才加入发布列表。

## 本轮自动检查

- 选择器中的每种语言须有与英语基准相同的应用和服务端键，且占位符一致。
- 拦截大量重复占位文本及大量未经翻译的英文文案。
- 检查文字体系匹配，避免把不同文字体系的同一语言误选为已支持的变体。
- 检查每种语言的安装清单、日期词包与常用组件辅助标签。
- 检查公开邮箱与登录页的语言传递，以及语言资源载入失败时显示已成功载入的语言。

自动测试和浏览器抽检只证明列出的场景；尚未逐句审定全部 16 种语言的每个控件与专业术语。扩大语言列表前仍需目标语言审阅。

本轮复查的其他 83 种隔离候选均未通过结构门槛；荷兰语与瑞典语候选虽通过主词典结构检查，仍有编辑器包错义及待审页面。候选未进入应用或安装清单。此后基准新增了两项账户删除提示，全部候选在再次评估前必须重新对齐最新版词典。账户删除页面会在确认前重新读取删除方式；服务端从 D1 直接读取当前方式，若确认后管理员改变设置，或旧页面未提供确认时的方式，便拒绝执行并提示重新查看。[D1 无会话查询默认走主库](https://developers.cloudflare.com/d1/best-practices/read-replication/)；[KV 在不同地区可能延迟传播](https://developers.cloudflare.com/kv/concepts/how-kv-works/)。

本地邮件历史只在当前浏览器配置文件或独立安装应用内保存，由用户手动清理。主屏幕应用的数据可能不会从浏览器迁移；文案分别描述存储范围，且提醒浏览器存储压力或清除站点数据仍可能移除副本。[WebKit 的安装应用存储说明](https://webkit.org/blog/14787/webkit-features-in-safari-17-2/)是这项提示的依据之一。

现有组件语言包中，与英语基准完全相同的字符串从 596 处降为 259 处。剩余项包含当前界面未使用的组件及合法同形词，不能直接当作 259 项错译；已对当前常用控件的关闭、分页、表格、日期、数字输入、下拉等辅助提示做专项检查。编辑器若无对应语言包会明确回退英语，不能算作该语言的完整覆盖。
